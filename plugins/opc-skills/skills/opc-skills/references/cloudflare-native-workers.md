# 原生 Workers 服务端迁移

在 [Cloudflare 部署与迁移](cloudflare-deployment.md) 判断迁移范围后，处理 API、认证、邮件、AI 或 Node 服务时读取本参考。沿用已有发布授权、默认分支与真实验收门禁；本文不授权搬库、购买套餐或新增第三方付费调用。

## 运行形态与兼容性

原服务按请求运行时，先验证原生 Workers 能否保持这种模型。Node/Express 项目不等于必须常驻容器；只有无法合理适配的二进制、系统能力或进程需求才进入容器评估，并解释闲置费和休眠时延。数据库继续托管在原平台是独立、有效的决策，不因应用迁移默认改为 D1。

- 按实际 lockfile、Wrangler 版本、`compatibility_date` 和 `nodejs_compat` 检查框架与依赖。能 import 或 dry-run 成功不能证明 API 可运行，有些 Node 模块只有 stub。先验证当前官方支持的 HTTP 适配路径，再决定是否重写框架。
- 检查原生扩展、图片处理、加密、模板/证书、动态加载和可写文件依赖；按需选择受支持的 JS/WASM、Images 或现有服务。构建时明确运行资源，不能把整个 Node 文件系统语义当成可用。
- 盘点 HTTP、SSE/WebSocket、上传、Cron、队列和后台任务各自的入口及生命周期。原来依赖进程常驻的工作需要另作设计，不能靠未等待的 Promise 保证执行。

## PostgreSQL 与请求生命周期

- 保留原项目、schema、角色与数据，分别验证预发/生产。Hyperdrive 是连接代理，不是搬库；用户未授权时不执行 DDL、数据复制或密码轮换。
- 按当前驱动文档接入 Hyperdrive，核对 TLS、原数据库区域、源连接预算与查询缓存。强一致读写和事务路径要显式决定缓存策略；不要机械叠加供应商 pooler，发生超时时用同库连接方案定位。
- 请求内创建和使用数据库连接，不跨请求复用不受支持的 I/O 对象。普通响应、错误、流正常结束及客户端取消都要释放连接；SSE 返回响应对象时流可能仍在工作，不能在 handler 的 `finally` 中过早关闭它。`waitUntil` 只按平台生命周期承接适当收尾，不作为无限后台任务。
- 验证事务、租户隔离、写后读、并发和取消后的副作用。健康接口成功不代替数据库业务验证。

## 契约、凭据与消费者

- 保持外部 API、用户映射、issuer/JWKS、签名/加密密钥和刷新契约，明确旧 token 的实际到期时间。迁移不自动授权重新签发所有身份或修改现有密钥。
- 沿真实入口核对 OAuth provider callback、回调转发和业务回跳。Apple 等 form POST 需要保留方法、表单字节、状态及 Location；错误 state 被拒绝不能替代有效账号完整登录。
- 核对服务间凭据在调用方与接收方均已配置，失败关闭；不仅检查健康接口。验证原对象读取、图片代理、签名下载及未授权拒绝，避免前端已迁但内部图片链仍失效。
- 明确环境变量的优先级与读取时机。检查通用 URL 是否覆盖环境专属 URL、env 是否在模块初始化前注入、CORS 是否覆盖实际新旧消费者；前端构建中不能保留旧平台 API。
- 配置检查只输出允许列出的公开入口、键名和存在性；连接 URL 可能包含密码，不能因为字段名含 URL 就整值打印。使用 secret/binding，不将服务端凭据写入静态产物。
- 按目标平台重新核对 Cron 语法、UTC 时区与原启停状态；迁移不能暗自启用原来停用的批量写入。

## 自动发布与可追踪版本

- 每个实际服务配置默认分支自动发布、明确环境与路径过滤。CI 的运行时/包管理器沿用项目 lockfile；部署前检查工作树和构建 source，避免构建期间的 checkout/commit 使产物映射失真。
- 区分源码 commit、产物摘要、Worker version 和 deployment，不能把它们互相替代。动态 Worker 可公开不含密钥的源码指纹；静态站可发布 `__deployment.json` 等产物来源文件。没有 `SOURCE_COMMIT` binding 不代表静态站没有来源，要读取它真实使用的证据。
- 默认分支自动发布至少实跑一次并读回线上来源，不能只验证 workflow 存在或手动发布成功。新链路通过后按迁移范围停掉旧平台重复构建，保留可用回滚版本；不要顺手停掉未迁系统。

## 测试、观察与成本

- 先用隔离预发数据和受保护的供应商替身验证完整调用链；受控 CRUD 后检查清理结果。静态预览关闭真实写作/发信，后端回归在隔离数据内验证真实读写。模型、邮件或图片付费验证按已授权的最小范围执行，复用已有图片，不因测试刷新重复生成。
- 覆盖旧会话、新登录、刷新、业务读写、并发、原对象读取、跨域与需要迁移的回调。取消测试要给上游明确延迟并检查取消后没有迟到写入；本地模拟与真实云端结果分别记录。
- 真实账号由用户完成的验证注明来源、日期、入口和范围，不冒充自动测试，也不外推为所有端都已验证。结合合成探针、DB after、日志窗口及域名/版本漂移检查完成 Release PR 核销。
- 同网络、输入、用户/权限和命中版本比较迁移前后；记录数据库区域、缓存、客户端总耗时与实际 CPU。小样本不是容量/SLO，首个请求不是受控冷启动。placement 优化先在预发回归流取消等正确性，失败就撤回。
- CPU 上限是预算保护，不是每请求固定计费，也不等于端到端响应时间。按当前官方规则区分计费请求、Worker 间调用方式、CPU、静态资源和共享额度，单独列出 PostgreSQL、模型、邮件、Images/R2/DO 等费用；不把所有 subrequest 一律当成计费请求。
- 区分账户已出账、本次可归属用量与月费情景；没有明细就明确无法归属，不能用账户某一张账单当本次总价。记录账户实际能力及临时 Containers/DO 等资源是否留存，不默认宣称零闲置费或无限部署。
- 主动探针同时检查 HTTP 状态、Worker 是否命中和运行时异常。平台 outcome ok 不等于 HTTP 全成功，采样错误日志要按请求分类；修复后重新观察。安全层在 Worker 前拒绝时区分浏览器与正常服务端客户端，不伪装指纹；确需调整则限于已定位的主机/规则，保留其它鉴权与防护。
