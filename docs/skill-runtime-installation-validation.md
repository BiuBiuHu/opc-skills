# 第二轮优化验证

## 范围与边界

统一授权判断、按实际能力接入 Subagent、提供带来源与本地规则合并的安装更新。生产环境、冻结候选、默认分支、预发/CR、真实回归、观察与归位约束保留。版本为 0.6.2；PR 不代表 npm 已发布，也不自动覆盖全局安装。

## 授权决策静态复核

| 输入场景 | 预期行为 |
|---|---|
| 已要求修复并提 PR，期间补写实施和测试记录 | 继续同范围实现/验证，不因文档完成再问 |
| 只要求方案或 validation-only | 交付分析，不编码或部署 |
| full-auto 但明确要求方案先审核 | 保留该审核关卡 |
| 已批准 Preview，未批准 Production | 不推定生产授权 |
| 已批准同环境、同范围、同冻结候选，补写证据 | 引用已有批准，继续技术检查 |
| 冻结候选、构建映射、alias 或发布范围改变 | 对受影响部分重新评审 |
| 费用、数据迁移或不可逆副作用扩大 | 只补充新增范围的授权 |
| 提问未回答或超时 | 不当作批准 |
| 只讨论 Subagent 工具升级 | 不实际启动子代理 |

以上为人工静态决策复核，不是独立模型行为测试。审批来源唯一化没有跳过任何技术发布检查。

## Subagent 接口复核

- 使用会话真实工具说明与 schema，示例以具备对应能力的 collaboration 宿主为条件。
- 通信和继续分开，等待通知不当成成功，interrupt 不当成 close。
- 未暴露创建/结果通道时主 Agent 独立完成；不通过 shell 模拟派生，也不虚构关闭能力。
- 用户明确许可、最小上下文、ownership、禁止生产动作和主 Agent 最终责任保留。
- 参数与语义按当前会话说明静态核对；本轮没有真实调用子代理。官方依据见编排 reference。
