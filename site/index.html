Codex Skill

From a pain point to a shippable release.

opc-skills is a Codex Skill for shipping consumer-facing apps together with their B-side operator consoles. It is for solo builders, one-person companies (OPC), and small teams that have to keep the product running after launch.

Who it is for

The skill covers user-side App / Web / mini-program / desktop work, the matching ops, review, config, and support consoles, and the primary API / auth / worker path behind them.

Solo builders and OPC

A complete path from a pain point to a shippable release, without turning the method into a private project dump.

Small teams

Ship a consumer product and the operator console that keeps it running—configuration, review, support, and release control included.

Evidence-first delivery

Work that needs real pages, real clients, staging, test reports, and production regression—not only a green build.

The delivery loop

The main agent reads SKILL.md and enters requirement validation, UI, architecture, implementation, testing, integration, release, or post-release content. Page release is never blocked by article work.

  1. 01

    Clarify

    Align on the user, the job, and the success path before writing a backlog of fields.

  2. 02

    PRD

    Lock the consumer journey and the operator loop that has to exist for that journey to stay alive.

  3. 03

    UI

    Prototype the consumer experience and the B-side console together, including empty, error, and slow states.

  4. 04

    Architecture

    Draw the call graph and change impact. Clients talk to the primary API; internal services stay behind it.

  5. 05

    Implement

    Move in controlled steps from a saved baseline. Project names and deployments stay in the project’s own facts.

  6. 06

    Test

    Choose the smallest sufficient set from changed files, call chains, and risk. A passing build is not the proof.

  7. 07

    Integrate

    Exercise real pages and real clients against staging and the real API, not a login screen alone.

  8. 08

    Release

    Staging evidence, review, release-plan sign-off, production smoke, then production-domain regression.

  9. 09

    Optional content

    After a completed release, Content Agent can suggest, draft, or publish bilingual notes. Publishing is never silent.

What you get

Reusable methods, gates, templates, and role placeholders. Not a hosted runtime and not a screenshot gallery of private products.

  • Templates Requirement validation, PRD, UI prototype, architecture, change impact, implementation plan, test strategy, release plan, evidence manifest, ops runbook, and post-release content.
  • Role files Explorer, Frontend, Backend, QA, Integration, DevOps, and Content. The skill does not call subagents itself; the main agent uses runtime tools only when you explicitly allow it.
  • Release integrity Reference plus a check script for candidate commit, deployment commit, default-branch merge, and worktree reconciliation.
  • One-command upgrade Upgrade an existing install to the latest version with one command. Local edits use a verified baseline and three-way merge; a conflict leaves every install unchanged and keeps backups.
  • Install surfaces CLI for install, update, and doctor, plus Cursor and Claude discovery directories. Optional Codex Agent Plugin install. This repo is not in the public Plugins Directory.
  • Product hosting Products this skill helps ship can deploy to Vercel or Cloudflare. Hosting follows the project; this marketing site is separate.

Evidence gates

  1. Real pages and clientsNot a mock-only walkthrough.
  2. StagingReal API, storage, and feature paths.
  3. Test reportScoped to the change, then recorded.
  4. Code reviewA reviewable diff, not a private patch.
  5. Release-plan sign-offRelated systems included or explicitly out of scope.
  6. Production smokeThe live entry, not only a health check.
  7. Production-domain regressionSmoke does not replace P0/P1 checks.
  8. Observation windowRelease is complete only after the window closes.

Install

Git and Python 3.9+ are required. The one-liner creates ~/.codex/skills if needed. After install, one command upgrades the installed skill to the latest version. doctor checks provenance, versions, and local overrides.

npx 
npx opc-skills install
curl 
curl -fsSL https://raw.githubusercontent.com/BiuBiuHu/opc-skills/main/scripts/install.sh | bash
upgrade 
npx opc-skills update

Upgrade an existing install

npx opc-skills update refreshes an existing install from a verified Git source cache and syncs already-present .agents, Cursor, and Claude skill surfaces. Per-install local edits use a verified baseline and three-way merge. Any conflict leaves all installations unchanged; backups are retained. You run this command yourself: it is not an unattended or background auto-update, and a product release does not overwrite the global skill. npx opc-skills doctor checks provenance, versions, and local overrides, and does not require .git in the installed directory.
